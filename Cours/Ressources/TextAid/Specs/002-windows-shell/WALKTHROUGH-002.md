# LOT-002 Windows walkthrough

Result: `src/TextAid.App/bin/Publish/TextAid.exe` (SHA-256 in `GATES-002.md`). Run `publish.ps1` to create it, then run the EXE on a Windows desktop with a usable notification area. The binary is the only required file in its publish directory.

Olivier confirmed the menu, theme, capture, tray actions, and About version on earlier candidates, then found that the previous EXE opened the session in the upper-left area, allowed multiple tray instances, and stopped responding to Ctrl+C+C after repeated launches. The current EXE fixes those paths. On this candidate Olivier confirmed no-selection invocation, Cancel and window-close behavior, centering, and rejection of a second instance. R-013 preserves no-selection invocation for later versions; manual typing is a possible later workflow, not a V0.1 requirement. The clean-machine check remains deferred under D-002 and R-012, without blocking the lot on its own; its pending status is in `PORTABILITY-CHECKS.md`.

1. Launch `TextAid.exe`. Confirm it stays resident, creates `%APPDATA%\TextAid\config.json`, and does not open the transaction window on launch. Launch the same EXE a second time; confirm it exits without adding another tray icon or keyboard hook.
2. Open Notepad or `tools/TextAid.TestTarget/bin/Debug/net10.0-windows/TextAid.TestTarget.exe`. Select some text. A single `Ctrl+C` should leave the source app unchanged and should not open TextAid. Hold Ctrl and press C twice within roughly 450 ms; confirm the captured text appears in TextAid. Repeat without selected text; the TextAid session must still open, although V0.1 does not yet support typing the input there.
3. Confirm the session window is fixed at 680 × 520 DIP, is not on the taskbar, cannot be minimized or resized, and appears centered in the work area of the monitor containing the focused source control. Repeat with the source on another monitor, ideally at a different scaling factor.
4. With the session visible, repeat the trigger. Confirm no second session appears. Confirm `Accept` is disabled in V0.1. Use `Cancel`, Escape, Alt+F4, and the window close button in separate runs; each must leave source text unchanged and permit a new session afterward.
5. Inspect the session window, title bar, text selection, disabled button, tray menu, Settings window, and About window for dark styling and readable focus/hover states. Check that tray separators are thin and muted with no white left gutter, and that the full About window surface is dark. Confirm the About logo, name, exact subtitle, version `0.1.0`, and clickable official product link.
6. In the tray menu, Disable and confirm the trigger does not invoke a session; Enable and confirm it does. Exit and confirm the tray icon disappears.
7. When a separate clean Windows x64 machine is available, copy the EXE alone to it and repeat launch and About without a separately installed .NET 10 runtime. Record the EXE hash and result in `PORTABILITY-CHECKS.md`. If unavailable, retain DEFERRED and revisit at the next opportunity, including a later release. This check does not by itself block G-002-003 or lot closure; the self-contained single-file build and publish requirements still apply.

Record the date, validator name, acceptance or specific corrections in G-002-003. A source-monitor and dark-theme acceptance is required before the lot can move to Ready-to-close.
